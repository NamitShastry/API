APIx Hackathon Study Guide (SIH26056)
Real-Time Airfare Price Index — What Each Sub-Team Needs to Learn
0. Recommendation on Data Collection (read this first)
Real scraping of IndiGo/MakeMyTrip/etc. involves anti-bot systems, CAPTCHAs, and fragile JS-heavy
pages — hard even for experienced engineers, and risky to attempt live in a short hackathon.
Recommended Path:
Primary plan: Build a mock data generator that simulates realistic fares (random walk pricing
with lead-time curves, day-of-week effects, occasional spikes) instead of live scraping. This lets
you build and demo the entire pipeline (cleaning → index → dashboard) reliably.
Stretch goal: Attempt one simple real scrape (e.g., a single OTA search page, using Playwright) to
prove the concept works, and fall back to mock data if it breaks.
Judges usually care more about the pipeline, index methodology, and dashboard than raw
scraping toughness — so don't let scraping eat your whole week.
Keep this in mind as you assign study time below: the backend team should split time between "real
scraping basics" and "mock data + pipeline," not spend it all on scraping.
1. Shared Foundations (everyone, ~1–2 days)
These are needed by all three teams before splitting off.
 Git & GitHub: clone, branch, commit, pull request, resolving merge conflicts
 JSON: reading/writing, nesting, how APIs exchange data

 Basic command line: navigating folders, running scripts, installing packages (pip/npm)
 How the whole system fits together (re-read the problem statement's "System Overview"
section as a team, and sketch the architecture diagram on a whiteboard)

Suggested schema to study/design together with backend team:
raw_fares : scrape_timestamp, origin, destination, carrier, flight_date, advance_days,
base_fare, taxes, total_fare, source

route_weights : origin, destination, weight (from DGCA data)
apix_daily : date, index_value, route (nullable for "overall")
Mini-project to practice: Create these 4 tables locally, insert some sample rows by hand, and write a
SQL query that computes a simple weighted average price per day.
5. Cross-Team Topics Worth a Group Session
CPI / index number methodology (30–45 min group study) — read up on how CPI sub-indices work
in general; you don't need to be economists, just understand "weighted average relative to a base
period."
How the pieces connect end-to-end: scraper/mock → raw DB table → cleaning script → cleaned
DB table → index script → apix_daily table → API → frontend chart. Draw this together so no
one is confused about data flow during integration.
API contract: agree early (before deep coding) on the exact shape of /api/index and 
/api/prices responses — this avoids frontend/backend integration pain later.
